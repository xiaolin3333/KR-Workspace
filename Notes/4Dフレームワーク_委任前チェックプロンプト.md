# 委任前チェックプロンプト（STEP1＋STEP2 統合版）

出典：Anthropic「4D AI Fluency Framework」（委任・説明・判断・責任）の記事より、
STEP1（工程分解と委任ラインの決定）とSTEP2（完成条件の先出し）を
1回のプロンプトで完結させるためのテンプレート。

## 使い方

1. 下の「プロンプト本体」をそのままコピーする。
2. 末尾の「### 仕事の内容」の下に、これから着手する仕事の内容（依頼文・下書き・史料整理の指示など）を貼り付ける。
3. AIに送る。返ってくるのは完成物ではなく、①工程分解表 ②委任ライン ③完成条件チェックリストの3点のみ。
4. その結果に自分で同意してから、初めて個別の作業（下書き作成・翻刻補助など）を依頼する。

このプロンプトの役割は「AIに仕事をさせる前の線引きをすること」であり、
成果物そのものを作らせることではない点に注意。ここで手を抜くと、
記事が指摘する「指示は増えるのに検証が減る」状態にそのまま陥る。

---

## プロンプト本体（コピペ用）

```
あなたには今から成果物を作らせない。まず以下の2つだけをやってほしい。

【前提】
・私はこれから下に貼る仕事に着手する。
・目的は「どこをAIに渡し、どこを自分の手に残すか」を先に決め、
　さらに「何がそろえば完成と言えるか」を作業前に文章化することだけ。
・下書きや草稿の作成、要約、翻刻・校訂・出典確認などの実作業は、
　この後の別の指示があるまで一切始めないこと。

【STEP1：工程分解と委任ラインの決定】
この仕事を、次の4つの工程に分解してください（内容に応じて工程名は調整してよい）。
　1. 材料集め（史料・先行研究・データの収集）
　2. 下書き（構成案・草稿・翻刻案などの一次生成）
　3. 確認（事実確認・出典照合・論理点検）
　4. 決定（最終的な採否判断・公開判断）

各工程について、次の3択のいずれかを提案してください。
　A. AIに渡してよい工程
　B. 自分（依頼者）が必ず手を動かすべき工程
　C. AIが下案を作り、依頼者が必ず検証・修正する共同工程

原則として、次の2つは自動的にBとして扱うこと（理由も一言添える）。
　・人の価値判断が入る工程（解釈、評価、優先順位づけ）
　・外部（査読者・審査者・読者・関係者）に出す直前の最終確認

【STEP2：完成条件の先出し】
下書きを1文字も書く前に、「何がそろっていれば合格か」を
箇条書きで5〜8項目、先に定義してください。含めるべき観点の例：
　・必須で参照・引用すべき先行研究や史料の範囲
　・避けるべき誤読・アナクロニズム・用語の混同
　・文体・分量・提出先の書式要件
　・事実確認が必須な数値・年代・固有名詞の扱い
　・「これが欠けていたら差し戻す」という具体的な不合格条件

【出力形式】
1. 工程分解表（工程名｜A/B/C区分｜理由を1行）
2. 完成条件チェックリスト（箇条書き）
のみを出力し、それ以外の下書きや提案文は書かないこと。

### 仕事の内容
（ここに、これから着手する仕事の内容を貼り付ける）
```

## 補足：STEP3との接続（参考）

STEP3（リスクの大きさに応じて確認の濃さを変える）は成果物が返ってきた後の話なので、
このプロンプートには含めていない。目安は以下の2段階のみ。

- 内部向け下書き・自分用メモ → 一部を抜き取って確認すれば足りる
- 外部に出すもの（審査書類・図録・査読投稿・金額や年代など事実性が問われる記述）→
  根拠（史料原文・一次資料・出典）まで自分の目でたどって確認する

STEP1・STEP2で「人が最終確認する」と決めた工程が、このSTEP3の対象になる。
